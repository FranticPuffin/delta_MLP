# Delta-MILP 调度系统参数说明

本文档汇总了 `delta_core.py` 中所有可配置参数、输入 JSONL 数据字段及其限制与约束关系。

---

## 一、调度器构造参数

在实例化 `DeltaMILPScheduler(data_path, total_horizon_hr, granularity_min)` 时传入。

| 参数名 | 类型 | 默认值 | 说明 | 限制与约束 |
|--------|------|--------|------|------------|
| `data_path` | `str` | 必填 | 输入 JSONL 数据文件路径 | 文件必须存在，且每行为一个合法的 JSON 对象 |
| `total_horizon_hr` | `float/int` | `168` | 总调度时间窗口（小时） | 必须 `> 0`；当前模型按周调度，默认 168 小时（7 天） |
| `granularity_min` | `float/int` | `15` | 时间粒度（分钟） | 必须 `> 0`；建议能被 `60` 整除；与 `total_horizon_hr` 共同决定时间帧数 `T = total_horizon_hr * 60 / granularity_min` |

### 约束关系
- `T = int(total_horizon_hr * 60 / granularity_min)` 必须为正整数。
- 时间粒度越小，变量规模越大，求解时间越长。

---

## 二、动态优化参数

在调用 `run_dynamic_optimization(...)` 时传入。

| 参数名 | 类型 | 默认值 | 说明 | 限制与约束 |
|--------|------|--------|------|------------|
| `data_path` | `str` | `Data/dsn_data.jsonl` | 输入数据文件路径 | 同构造参数 |
| `eta` | `float` | `0.15` | 初始满意度阈值 | 必须满足 `0 < eta < 1`；建议 `0.05 ~ 0.5` |
| `eta_plus` | `float` | `0.05` | 每次达标后阈值增量 | 必须 `> 0`；过大会导致最终阈值无法达到 |
| `k_max` | `int` | `10` | 最大迭代次数 | 必须 `> 0`；越大越可能找到更高满意度均衡，但耗时线性增加 |
| `output_csv` | `str` | `"dsn_schedule.csv"` | 输出调度表 CSV 文件名 | 可自定义路径；运行时覆盖 |
| `redirect_stdout_to_log` | `bool` | `True` | 是否将标准输出重定向到日志文件 | API 调用建议设为 `False` |
| `open_viewer` | `bool` | `False` | 是否自动打开甘特图查看器 | API 调用必须设为 `False` |

### 约束关系
- `eta + k_max * eta_plus` 理论上可以接近 `1`，但实际受任务资源和优先级分布限制。
- 若 `eta_plus` 过大或 `k_max` 过小，算法可能来不及收敛到高阈值。

---

## 三、求解器参数

| 参数/常量 | 位置 | 默认值 | 说明 | 限制与约束 |
|-----------|------|--------|------|------------|
| `_GLPK_PATH` | `delta_core.py` | 自动探测 | GLPK 求解器可执行文件路径 | 自动探测顺序：`./glpk/glpsol.exe` > 系统 PATH > 默认 `glpsol` |
| `--tmlim 60` | `solve()` | `60` 秒 | 单次 MILP 求解时间上限 | 必须 `> 0`；问题规模大时建议增大 |
| 资源容量约束 | `solve()` | `40 * 168 * 0.7` | 总天线资源容量上限 | 假设 40 台天线，70% 利用率；修改需同步调整实际天线数量 |

### 约束关系
- GLPK 为当前默认求解器；若更换为国产求解器，需要保证其支持 PuLP 接口或提供兼容的 MPS/LP 文件解析方式。
- 资源容量 `40 * 168 * 0.7` 为全局硬约束，任何调度结果都不能突破该上限。

## 四、输入数据字段（JSONL）

每行一个 `mission` 对象，包含以下字段。

### 4.1 任务级参数（Mission Level）

| 字段名 | 类型 | 是否必填 | 说明 | 限制与约束 |
|--------|------|----------|------|------------|
| `mission_id` | `str` | 是 | 任务唯一标识符 | 允许中文、英文、数字、下划线；内部会被编码为 ASCII 安全名 |
| `base_priority` | `int` | 否（默认 3） | 任务基础优先级 | 必须在 `{1,2,3,4,5}` 范围内；`5` 为最高 |
| `total_requested_hr` | `float` | 是 | 该任务一周内请求的总通信时长 | 必须 `> 0`；作为满意度分母 |
| `priority_schedule` | `list[dict]` | 否 | 任务优先级时变计划 | 每个元素必须包含 `start_hr`、`end_hr`、`priority`；时间段不应重叠 |
| `activities` | `list[dict]` | 是 | 该任务包含的活动列表 | 至少包含一个活动 |

#### `priority_schedule` 子字段

| 字段名 | 类型 | 说明 | 限制 |
|--------|------|------|------|
| `start_hr` | `float` | 优先级生效起始时间（小时） | `>= 0`，且 `< end_hr` |
| `end_hr` | `float` | 优先级生效结束时间（小时） | `<= total_horizon_hr` |
| `priority` | `int` | 该时段优先级 | 必须属于 `{1,2,3,4,5}` |

### 4.2 活动级参数（Activity Level）

| 字段名 | 类型 | 是否必填 | 说明 | 限制与约束 |
|--------|------|----------|------|------------|
| `activity_id` | `str` | 是 | 活动唯一编号 | 允许中文；同一 mission 内建议唯一 |
| `prior` | `int` | 否（默认取 `base_priority`） | 活动峰值优先级 | 必须属于 `{1,2,3,4,5}` |
| `d_min` | `float` | 是 | 最小连续通信时长（分钟） | 必须 `> 0` |
| `d_max` | `float` | 是 | 最大连续通信时长（分钟） | 必须 `>= d_min` |
| `setup_min` | `float` | 是 | 通信前准备时间（分钟） | 必须 `>= 0` |
| `teardown_min` | `float` | 是 | 通信后拆除时间（分钟） | 必须 `>= 0` |
| `can_split` | `bool` | 是 | 是否允许拆分为两个子活动 | `True` 时生成 XOR 变量对；`d_max` 较大时通常设为 `True` |
| `prefer` | `int` | 否（默认 2） | 天线类型偏好 | 必须属于 `{0,1,2}`：`0` 中继星、`1` 地面站、`2` 无偏好 |
| `view_periods` | `list[dict]` | 是 | 该活动可选的天线视图窗口 | 至少包含一个窗口 |

### 4.3 视图周期参数（View Periods）

| 字段名 | 类型 | 是否必填 | 说明 | 限制与约束 |
|--------|------|----------|------|------------|
| `antenna` | `str` | 是 | 天线名称 | 不能为空；同一活动多个窗口可重复 |
| `antenna_type` | `int` | 否（默认 1） | 天线类型 | 必须属于 `{0,1}`：`0` 中继星、`1` 地面站 |
| `start_hr` | `float` | 是 | 可见窗口起始时间（小时） | `>= 0` 且 `< end_hr` |
| `end_hr` | `float` | 是 | 可见窗口结束时间（小时） | `<= total_horizon_hr` 且 `> start_hr` |

## 五、关键约束关系总结

1. **满意度计算**
   ```
   satisfaction[mission_id] = 已调度时长 / total_requested_hr
   ```
   其中 `total_requested_hr > 0`。

2. **时间窗口约束**
   - 所有 `start_hr`、`end_hr` 必须在 `[0, total_horizon_hr]` 内。
   - 活动实际调度区间：`[start_hr, start_hr + d_max]`，且不能超过 `view_periods[i].end_hr`。

3. **时长约束**
   - 调度时长 `duration` 必须满足：`d_min <= duration <= d_max`。
   - 拆分后每个子活动时长约为 `d_max / 2`。

4. **资源互斥约束**
   - 同一天线在同一时刻只能服务一个活动。
   - 同一任务（mission）在同一时刻只能占用一根天线。
   - 资源占用区间包含 `setup` 和 `teardown`。

5. **天线偏好约束**
   - `prefer=0`：优先/强制使用 `antenna_type=0` 的窗口；无可用时回退。
   - `prefer=1`：优先/强制使用 `antenna_type=1` 的窗口；无可用时回退。
   - `prefer=2`：无偏好。

6. **拆分约束（XOR）**
   - 若 `can_split=True`，原始活动与拆分后的两个子活动最多只能调度其中一组。
   - 两个子活动必须成对调度：`x[a_prime] == x[a_dprime]`。

7. **目标函数**
   ```
   max Σ (iter_weight[m] * priority_weight[a]^2 * split_factor * x[a])
   ```
   - `iter_weight[m]`：动态权重迭代中根据满意度调整。
   - `priority_weight[a]`：活动优先级平方。
   - `split_factor`：拆分活动权重为 `0.5`，原始活动为 `1.0`。

8. **全局资源容量**
   - 总调度时长（含拆分）不能超过 `40 * 168 * 0.7 = 4704` 小时。

---

## 六、参数调整建议

| 场景 | 建议调整 |
|------|----------|
| 求解时间过长 | 增大 `granularity_min` 或减小 `k_max`；或增大 `--tmlim` |
| 低优先级任务全部被舍弃 | 降低 `eta` 或减小 `eta_plus` |
| 高优先级任务未达标 | 检查 `base_priority`/`prior` 是否设置正确；增大 `k_max` |
| 中文 mission 显示方块 | 系统中安装 SimHei/Microsoft YaHei 等中文字体，或修改 `set_ch_font()` 候选字体 |
| 需要替换求解器 | 修改 `solve()` 中的 `solver = pulp.GLPK_CMD(...)` 为对应求解器接口；需保证变量名编码兼容性 |

---

## 七、待扩展：国产求解器替换说明

当前实现默认使用 GLPK 作为 MILP 求解器。若需替换为国产求解器（如 MindOpt、COPT、杉树求解器等），主要修改点：

1. 在 `solve()` 中替换 `pulp.GLPK_CMD(...)` 为对应求解器调用。
2. 若国产求解器不直接支持 PuLP，可将问题导出为 `.lp` 或 `.mps` 文件，再调用其命令行/接口求解，最后读取结果。
3. 确保所有决策变量名仍通过 `_encode_id()` 保持 ASCII 安全。
4. 根据国产求解器的授权方式，配置 license 路径或环境变量。

> 注：具体实现取决于所选求解器的 Python API 形态，建议在确定求解器后再进行适配。
